## 🏡 ДЗ №1: Прогнозування вартості нерухомості (California Housing)

### 🎯 Опис задачі

Побудова прогностичної моделі для оцінки медіанної вартості будинків (`MedHouseVal`) у Каліфорнії. Проект фокусується на вирішенні проблеми нелінійності географічних даних, суворій оптимізації пам'яті (RAM) та побудові production-ready конвеєрів (Zero-Trust ETL).

---

### 🧮 Математичне та Геопросторове ядро (Feature Engineering)

Щоб моделі могли повноцінно зрозуміти складну економічну географію Каліфорнії, ми відмовилися від сирих координат і реалізували **подвійний просторовий аналіз**:

**1. Макро-рівень (Формула Гаверсина)**
Замість звичайної евклідової відстані на площині, ми розраховуємо реальну фізичну відстань по сфері Землі від кожного будинку до найбільших економічних хабів (Лос-Анджелес та Сан-Франциско). 
Математична імплементація:

$$d = 2R \arcsin \left( \sqrt{ \sin^2\left(\frac{\varphi_2 - \varphi_1}{2}\right) + \cos(\varphi_1)\cos(\varphi_2)\sin^2\left(\frac{\lambda_2 - \lambda_1}{2}\right) } \right)$$

*де $R = 6371.0$ км (радіус Землі), $\varphi$ — широта, $\lambda$ — довгота.*

Це створює потужну макроекономічну ознаку `Dist_to_Hub`.

**2. Мікро-рівень (DBSCAN Кластеризація щільності)**
Замість класичного K-Means ми використали просторову кластеризацію **DBSCAN**.

- **Чому не K-Means?** K-Means шукає сферичні кластери, що суперечить витягнутій береговій лінії Каліфорнії. DBSCAN групує райони за *щільністю забудови*, ідеально огинаючи океан та автоматично маркуючи пустельні зони як "шум" (outliers), що значно підвищує точність алгоритмів.

**3. Стабілізація дисперсії (Target Transformation)**

Розподіл цін на нерухомість має сильний зсув вправо (Right-Skewed). Для стабілізації дисперсії та покращення збіжності градієнтних алгоритмів реалізовано динамічну трансформацію цільової змінної:

$$y_{trans} = \ln(1 + y) \quad \text{або} \quad y_{trans} = \sqrt{y}$$

Моделі навчаються у трансформованому просторі, а під час інференсу застосовується зворотне перетворення (наприклад, $\exp(y_{trans}) - 1$), що гарантує розрахунок метрик (MAE) у реальних доларах США.

### 🚀 MLOps та Архітектурні нововедення

- **Zero-Trust ETL Конвеєр (`SecureDownloader`):** Дані завантажуються через кастомний 5-рівневий смарт-маршрутизатор (Smart Router). Він захищає від пошкоджених архівів (перевірка CRC32), підтримує дозавантаження при обривах зв'язку (HTTP Range) та автоматично перемикається між Kaggle API, GDrive та прямими посиланнями.
- **Micro-Memory Optimization (Pandas CoW):** Активовано режим `pd.options.mode.copy_on_write = True`, що запобігає прихованому дублюванню DataFrame-ів у пам'яті під час ETL-трансформацій.
- **Кастомні MLOps Трансформери (`SpatialEngineer`):** Уся логіка розрахунку дистанцій за Гаверсином інкапсульована у Scikit-Learn сумісний клас `BaseEstimator`. Це дозволяє серіалізувати математику разом із вагами моделі (через `joblib`).
- **Native Pandas API (Scikit-Learn 1.9.0):** Активовано `set_config(transform_output="pandas")`. Усі трансформери зберігають імена колонок та індекси, усуваючи "чорні ящики" з Numpy-масивами на виході пайплайну.
- **Track & Tune (MLflow + Optuna):** Інтегровано локальну SQLite-базу MLflow для трекінгу експериментів Байєсівської оптимізації алгоритмом TPE (Tree-structured Parzen Estimator).

### 🔬 Архітектурний A/B Тест: OHE vs Native Categoricals

У проекті реалізовано роздвоєння (Forking) пайплайну даних для прямого порівняння двох інженерних підходів:

1. **Шлях А (`df_ohe`):** Класичний One-Hot Encoding. Роздуває матрицю (створює десятки розріджених колонок), але є математично обов'язковим для лінійного сімейства алгоритмів та нейромереж.
2. **Шлях Б (`df_native`):** Сучасний підхід для алгоритмів дерев. Колонка `GeoCluster` отримує тип `category`.

    - **Перевага:** Кардинальне зменшення споживання RAM. XGBoost (з `enable_categorical=True`) та LightGBM самостійно оптимізують спліти, ігноруючи неефективний One-vs-Rest підхід OHE.

### 🏆 Бенчмаркінг та Пояснюваний ШІ (XAI)

У пайплайн інтегровано понад **30 архітектур**, починаючи від класичної `OLS` регресії до `Explainable Boosting Machine (EBM)` від Microsoft та екстремальних бустингів (`XGBoost`, `LightGBM`).

Для захисту рішень моделі перед стейкхолдерами розроблено модуль **Explainable AI (XAI)**:

1. **Динамічний аналіз важливості:** Автоматичний роутинг метрик (`|coef_|` для лінійних, `Information Gain` для дерев, та `Permutation Importance` для чорних скриньок типу MLP).
2. **Квантова пояснюваність (SHAP):** Розрахунок маргінального внеску кожної ознаки для окремо взятого будинку на основі теорії кооперативних ігор Шеплі:

    $$\phi_i = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!(|F| - |S| - 1)!}{|F|!} \left[ f(S \cup \{i\}) - f(S) \right]$$

3. **Генеративне 3D Мистецтво ("Цифровий Бонсай"):** Унікальна WebGL візуалізація, що динамічно витягує справжню архітектуру (всі `n_estimators` та гілки розгалужень) натренованого ансамблю дерев у тривимірний фрактальний простір.

**Аналіз залишків (Residual Plot):** Візуальна перевірка на гомоскедастичність доводить, що модель дещо недооцінює "елітний" сегмент нерухомості (через історичне цензурування цін набору даних на рівні $500,000), що є критичним інсайтом перед розгортанням у Production.

### 📊 Висновки (Академічні вимоги vs Production)

В рамках виконання базового завдання було проведено очистку даних (через `scipy.stats.zscore` для `AveRooms`, `AveBedrms`, `AveOccup`, `Population`), видалено мультиколінеарні ознаки та застосовано `StandardScaler`. Навчання базової `LinearRegression` на очищених даних дозволило досягти очікуваного покращення метрик:

- **R²** зріс на ~3-5 відсоткових пунктів.
- **MAE** та **MAPE** пропорційно знизились порівняно з неочищеним бейзлайном.

**Однак, лінійна регресія має фундаментальні обмеження** при роботі з геопросторовими даними (координатами) та нелінійними залежностями. Тому, для досягнення метрик рівня Production, базовий пайплайн було масштабовано:

1. **Відмова від сирих координат:** Впровадження дистанції Гаверсина та DBSCAN-кластеризації дало значно більший приріст R², ніж просте видалення корелюючих колонок.
2. **Заміна моделі:** Перехід від `LinearRegression` до ансамблевих методів з градієнтним бустингом (`XGBoost`, `LightGBM`) дозволив алгоритмам самостійно знаходити нелінійні взаємодії між ознаками, що зменшило MAE до індустріальних стандартів оцінки нерухомості.
3. **Обробка цільової змінної:** Логарифмування зсунутого вправо розподілу цін (`MedHouseVal`) стабілізувало дисперсію та дозволило моделі точніше прогнозувати дорогий сегмент нерухомості, який класична лінійна регресія сильно недооцінювала.
