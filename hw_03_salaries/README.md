## 💼 ДЗ №3: Прогнозування зарплат (Salaries Estimation)

### 🎯 Опис задачі

Побудова прогностичної моделі регресії для оцінки рівня заробітної плати співробітників компанії (`Salary`) на основі алгоритму K-Nearest Neighbors (KNN). Проєкт фокусується на вирішенні проблеми "Прокляття розмірності" (Curse of Dimensionality), трансформації ознак для коректного обчислення математичних дистанцій та побудові інтерактивного MLOps-пайплайну.

---

### 🧮 Математичне ядро: Трансформації та Дистанції

**1. Розрахунок багатовимірної відстані (KNN)**
Алгоритм K-Nearest Neighbors не використовує градієнтний спуск чи ваги. Його логіка базується на пошуку "близнюків" у багатовимірному корпоративному просторі за допомогою Евклідової відстані. Для двох співробітників $p$ та $q$ з $n$ ознаками (досвід, освіта, тощо) вона обчислюється як:

$$d(p, q) = \sqrt{\sum_{i=1}^n (q_i - p_i)^2}$$

*Проблема:* Якщо не масштабувати дані, фінансові показники (в десятках тисяч) повністю знівелюють значення досвіду (в роках).

**2. Вирівнювання простору (Yeo-Johnson PowerTransformer)**
Для розв'язання проблеми масштабу ми використали не класичний `StandardScaler`, а нелінійну трансформацію Yeo-Johnson. Вона приводить розподіл числових ознак $y_i$ до Гаусового (нормального), що є ідеальною умовою для алгоритмів на базі дистанцій:

$$y_i^{(\lambda)} = \begin{cases} 
\frac{(y_i + 1)^\lambda - 1}{\lambda} & \text{якщо } \lambda \neq 0, y_i \ge 0 \\
\ln(y_i + 1) & \text{якщо } \lambda = 0, y_i \ge 0 \\
-\frac{(-y_i + 1)^{2-\lambda} - 1}{2-\lambda} & \text{якщо } \lambda \neq 2, y_i < 0 \\
-\ln(-y_i + 1) & \text{якщо } \lambda = 2, y_i < 0
\end{cases}$$

**3. Оцінка бізнес-результату (MAPE)**
Для валідації прогнозу заробітної плати розраховується середня абсолютна відсоткова помилка. Вона дозволяє інтерпретувати точність алгоритму у зрозумілому для бізнесу форматі (похибка прогнозу на рівні 3-5%):

$$\text{MAPE} = \frac{1}{n} \sum_{i=1}^n \left| \frac{y_i - \hat{y}_i}{y_i} \right| \times 100\%$$

---

### ⌛️ Інженерія часових ознак (Temporal Feature Engineering)

Хоча базовий алгоритм KNN розраховує дистанції між статичними характеристиками працівників у багатовимірному просторі, ми свідомо заклали часову динаміку для тестування фундаментальних моделей прогнозування:

**1. Часовий фактор інфляції заробітних плат**
За допомогою адаптера `get_salary_mock` створено синтетичний набір даних, який включає дату найму (`Hire_Date`). Окрім складної нелінійної функції ціноутворення, яка залежить від досвіду та освіти, алгоритм генерації враховує щорічний фактор інфляції на рівні 4% починаючи з 2015 року. Це створює реалістичний тренд зростання базової ставки, який класичні регресори без фактора часу можуть пропустити.

**2. Трансформація числових та категоріальних ознак (Просторовий препроцесинг)**
Для коректної роботи KNN впроваджено специфічний трансформаційний граф:
   - Числові дані проходять через `PowerTransformer` (метод Yeo-Johnson), який не просто масштабує ознаки, а приводить їхні "хвости" до нормального (Гаусового) розподілу. Це критично для обчислення Евклідової відстані.
   - Категоріальні дані (наприклад, департаменти) перетворюються за допомогою `TargetEncoder`, що кодує текстові назви через середню заробітну плату відповідної категорії, формуючи ідеальну числову шкалу.

Вона проектує співробітників у багатовимірний простір і "лазерними променями" показує математичні відстані до знайдених сусідів, з доходів яких формується фінальний прогноз моделі.
- **Permutation XAI:** Інтеграція модуля перестановочної важливості (Permutation Importance) дозволила агностично визначити, які саме фактори (наприклад, посада чи досвід) мають найбільший внесок у розмір заробітної плати, роблячи "чорну скриньку" KNN прозорою для бізнесу.

### 📊 Висновки (Академічні вимоги vs Production)

В рамках виконання базових академічних вимог завдання розв'язано повністю: набори даних було успішно завантажено, виконано EDA та обрано релевантні поля. Було застосовано конвеєр для нормалізації та кодування даних (`ColumnTransformer`) і навчено базову модель `KNeighborsRegressor`. Прогноз на нових валідаційних даних продемонстрував необхідну точність, не порушивши послідовність етапів машинного навчання.

**Проте, для досягнення рівня Production, архітектуру було кардинально розширено:**

1. **Боротьба з "Прокляттям розмірності":** Застосування `PowerTransformer` замість звичайного скейлера дозволило вирівняти зсунуті розподіли фінансових даних, значно зменшивши геометричну похибку при розрахунку найближчих сусідів.
2. **Байєсівська оптимізація (Optuna):** Відбувся перехід від жорстко заданого $K=5$ до інтерактивного селектора. Фреймворк Optuna автоматично підбирає оптимальну кількість сусідів та метрику дистанції (Евклідова чи Мангеттенська) з паралельним логуванням в MLflow.
3. **TimesFM Zero-Shot Forecast:** Враховуючи синтезований фактор дати найму, до архітектури було додано фундаментальну модель Google TimesFM. Вона, агрегувавши історичні дані без специфічного донавчання, змогла згенерувати 24-місячний прогноз зростання базових ставок (інфляції зарплат).
4. **Стовідсоткова готовність до деплою:** Замість ізольованого Python-скрипта, проєкт динамічно створює Dockerfile та Pydantic-схеми, дозволяючи за лічені секунди розгорнути натреновану модель на будь-якому хмарному сервері.
